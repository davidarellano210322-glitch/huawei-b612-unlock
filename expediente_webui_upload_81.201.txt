1) DESCUBRIMIENTO CLAVE: EL MECANISMO QUE USA inst_webui
---------------------------------------------------------------------
El WebUI COMPLETO (extraído del firmware 11.195 modded, webui_full/)
sí tiene la página real de update local (update_local.html + update_local.js).
Su mecanismo es:

  1. El usuario elige archivo .zip/.bin → el JS pone el campo oculto
     cur_path = "OU:" + <nombre del archivo>  ("OU" = Online Update)
  2. Al pulsar "Actualizar", hace POST multipart a:
        /api/filemanager/upload
     con:
        csrf_token = "csrf:" + <token de api/webserver/token>
        cur_path   = "OU:<archivo>"
        uploadfile = <el archivo>
  3. La respuesta debe contener "ok" (si no, falló).
  4. Luego hace polling de:
        /api/monitoring/check-notifications  → OnlineUpdateStatus
        /api/online-update/status            → CurrentComponentStatus
     códigos: 10 idle · 20 fallo · 30/40/50/52 descargando/listo ·
     60 instalando · 70/80 fallo · 90/100 éxito.

CONCLUSIÓN: la herramienta "WEB UI Exe setup" (inst_webui_2019-08-01.rar)
NO hace nada mágico: replica este POST multipart al handler de subida
del WebUI. Y en las rondas anteriores ESTE endpoint NUNCA se probó:
el barrido (endpoints_b612.py) solo hizo GET con las rutas que aparecían
en el JS del router Entel (stripped), y la lista de uploads probados
(/, /update, /api/update/upgrade-file, /cgi-bin/upgrade, /upload)
no incluye /api/filemanager/upload.

4) CONFIRMACIÓN DEL FLUJO 4PDA (por qué importa el orden)
---------------------------------------------------------------------
Post del hilo (usuario que flasheó todo): "from 11 mod to 81.201 mod
patch 3.9 first the original 81.201 then again update local webui then
flash the 81.201 mod — you always have to do that".

O sea: si el update local web por api/filemanager/upload funciona, el
orden correcto es:
  1) flashear original 81.201 (USB/balong), o subirlo por web,
  2) update local del WebUI,
  3) flashear el Mod3-9.
El WebUI NO cambia solo con flashear el mod: hay que actualizarlo aparte.
Esto explica por qué los intentos web anteriores con el mod directo
fracasaban: además del modelo B612__0 vs B612__1, faltaba el paso del
WebUI.
